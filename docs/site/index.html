Features

The plugin attaches a Socket.IO server to Strapi's HTTP server. Admin settings control connection policy, content-type events, rooms, namespaces, and monitoring.

01

Content events

Configured content types can emit singularName:create, singularName:update, and singularName:delete events after database lifecycle operations.

02

JWT handshake

Clients may send a users-permissions JWT in Socket.IO's auth.token. Invalid supplied tokens are rejected. Authentication can also be required in settings.

03

Rooms and namespaces

Configure role-based auto-join rooms and optional namespaces. Clients can request room joins only for rooms configured for their role.

04

Monitoring

The admin view reports connections, room counts, event totals, and a bounded in-memory event log. Monitoring snapshots omit socket IDs, addresses, tokens, and user identifiers.

Delete event scope: this fork currently emits delete events with strapi.$io.raw() on the root namespace. That path broadcasts to connected root-namespace clients instead of applying create/update role-room authorization. Do not enable delete events for sensitive content until that behavior has been reviewed or changed.

Install and connect

This checkout is the Schero94 fork. Its package name matches the upstream package, but the fork does not publish to npm.

Upstream package: npm install strapi-plugin-io installs the public upstream package, not this fork.

For local work on this fork, clone the Schero94 repository, install its dependencies, build it, then add its local package directory to your Strapi project.

Build the fork locallyNode 22
cd strapi-plugin-io
npm ci
npm run build

# In the Strapi application, use the local package directory
npm install --save file:../strapi-plugin-io

Enable the plugin in config/plugins.js or config/plugins.ts.

config/plugins.js
module.exports = ({ env }) => ({
  io: {
    enabled: true,
  },
});

Open the Strapi admin and go to Settings → Socket.IO to configure content types and role permissions. Runtime CORS, connection, security, room, namespace, Redis, and monitoring settings are stored by the plugin. Legacy contentTypes, events, hooks, and socket config fields are accepted by the config schema but are not applied by the current bootstrap.

Connect from a JavaScript client
import { io } from 'socket.io-client';

const socket = io('https://cms.example.com', {
  auth: { token: usersPermissionsJwt },
});

socket.on('article:create', (article) => {
  console.log('Created article:', article);
});

Configuration

Use the plugin settings screen to set runtime policies. These are the current defaults and server behavior.

SettingCurrent default or behavior
corsOrigin allowlist defaults to http://localhost:3000. Wildcard and non-HTTP(S) origins are discarded. Allowed methods are restricted to known HTTP verbs.
connectionMaximum 1,000 connections per server process; ping timeout 20 seconds, ping interval 25 seconds, and connection timeout 45 seconds.
rolePermissionsPublic and authenticated roles can connect by default. Configure each role's permitted content-type actions and room access deliberately.
rooms.autoJoinByRoleMaps normalized role names to room names. Client room joins are limited to that role's configured list.
entitySubscriptionsEnabled by default, with at most 100 subscriptions per socket and entity existence verification enabled. A role must have configured content-type actions.
securityAuthentication and event rate limiting are off by default. IP allowlists and blocklists are empty.
redisDisabled by default. When enabled, the adapter uses the configured Redis URL or redis://localhost:6379.
monitoringConnection logging is on, event logging is off, and the event log holds up to 100 entries by default.

Scale across Strapi instances

Enable Redis in settings and set a private Redis URL reachable by every Strapi instance. Each instance creates publisher and subscriber clients and installs the Socket.IO Redis adapter. If adapter initialization fails, the plugin logs an error and continues without it. Configure load-balancer session affinity when Socket.IO polling is enabled.

Settings shape
{
  "redis": {
    "enabled": true,
    "url": "redis://redis.internal:6379"
  },
  "security": {
    "requireAuthentication": true,
    "rateLimiting": {
      "enabled": true,
      "maxEventsPerSecond": 10
    }
  }
}

Security

CORS controls browser origins. It does not authenticate a socket or authorize access to content.

Authentication

Send a users-permissions JWT as auth.token, not as a query parameter. Set security.requireAuthentication when anonymous connections are not appropriate. Invalid supplied tokens are rejected instead of falling back to public access.

Room access

Use role-specific room allowlists. Room names are limited to 128 alphanumeric, underscore, or hyphen characters. Private messages require authenticated sockets with the same role and are limited to 2,000 characters.

Network and rate controls

Set exact HTTPS origins, enable IP allowlists or blocklists where useful, and enable per-socket event rate limiting. Keep Redis private and protect it according to your infrastructure.

Monitoring data

Monitoring output uses aggregate room and connection data. Event logs retain only an allowlist of fields and stay in process memory, not durable storage.

Review the delete-event behavior above before enabling delete notifications for protected or personal data. The current path broadcasts a minimal identifier payload to root-namespace clients.

API and events

The Socket.IO server is available as strapi.$io after plugin bootstrap.

CallPurpose
strapi.$io.joinRoom(socketId, room)Join a connected socket to a room from server-side code.
strapi.$io.leaveRoom(socketId, room)Remove a connected socket from a room.
strapi.$io.getSocketsInRoom(room)Return connected socket IDs and attached user objects for the room.
strapi.$io.sendPrivateMessage(socketId, event, data)Emit an event to a socket ID from server-side code.
strapi.$io.emitToNamespace(name, event, data)Emit to a configured namespace. The root namespace is named main in the helper map.
strapi.$io.emitToEntity(uid, id, event, data)Emit to the entity room uid:id. Server-side callers must enforce their own authorization.

Client room and entity events

Room join and entity subscription
socket.emit('join-room', 'members', (result) => {
  if (!result.success) console.error(result.error);
});

socket.emit('subscribe-entity', {
  uid: 'api::article.article',
  id: 'article-document-id',
}, (result) => {
  if (result.success) console.log('Subscribed:', result.room);
});

socket.on('article:update', (article) => {
  console.log('Article update:', article);
});

Entity subscription requests validate the UID and ID, check that the content type exists, check the role's configured content-type actions, and verify the entity by default. The subscription limit is capped at 500 even if a larger value is configured.

The config schema still accepts events and hooks fields for compatibility, but the current bootstrap does not register those handlers. Use server-side Socket.IO listeners in your application when you need custom event handling.
